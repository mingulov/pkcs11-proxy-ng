# Script inventory

These tools support building, testing, maintaining, and releasing the standalone
repository. Paths in the tables are relative to `scripts/`. CI connections below
describe the checked-in workflows; they are not claims about a completed CI run.

## CI and release entry points

| Script | Caller / purpose |
| --- | --- |
| `audit-test-workspaces.sh` | `ci.yml` and `nightly.yml`: audit/deny the standalone test workspaces; also called by `test-matrix.sh` |
| `packaging-smoke.sh` | `ci.yml` and `test-matrix.sh`: packaging/version consistency |
| `musl-dynamic-link-flags.sh` | `ci.yml` and `run-musl-test.sh`: common musl link flags |
| `ci-direct-vs-proxy.py` | `cross-platform.yml`: native direct-versus-proxied provider comparisons |
| `test-matrix.sh` | `nightly.yml` and `Dockerfile.test`: local CI gates and provider/consumer lanes |
| `run-test-tiers.sh` | `nightly.yml`: live test lanes; also a manual unit/integration/regression runner |
| `verify-release-subject.sh` | `release.yml`: validate the tag subject and version mirrors |
| `release-dry-run.sh` | `release.yml`: build and stage the Linux artifacts; also useful locally |
| `release-windows.sh` | `release.yml`: build and stage the Windows ZIP |

The GitLab pipeline builds the Alpine and Amazon carrier images through their
packaging Dockerfiles. GitHub's packaging smoke gate checks their source metadata.
The authoritative release order and evidence requirements are in the
[`0.x` beta release checklist](../doc/release/0.x-beta-release-checklist.md).

## Generated results and historical tooling

- `perf/results/` is generated by the manual harnesses and ignored by Git.
  Historical CSV/JSON measurements are archived in the `pkcs11-proxy-ng-ws`
  planning workspace, alongside their provenance.
- The unused `kryoptic-version.env` and older `Dockerfile.kryoptic` were archived
  in that workspace. The active provider builds are in
  [`Dockerfile.test`](../Dockerfile.test) and the
  [consumer fixture](../tests/consumers/Dockerfile.daemon.kryoptic).

Scripts stay with their callers so a standalone checkout keeps its validation
and release tooling. Archived results and planning notes are not build inputs.
