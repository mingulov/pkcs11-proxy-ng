# v0.2.1 Release Notes

**Status: `v0.2.1` release candidate; unpublished.** The source and packaging
versions are already `0.2.1`; publication remains gated by the quality receipt,
provider evidence, and tag procedure in the
[`0.x` release checklist](0.x-beta-release-checklist.md). This candidate
supersedes the unpublished `v0.2.0` candidate; limits recorded in the
[v0.2.0 notes](v0.2.0-release-notes.md) still hold except where this file says
otherwise.

Use one logical client in one trusted security domain per daemon and provider
instance. Restart the daemon and provider before switching independent clients
or domains. Do not share an instance among mutually untrusted clients.
`[proxy] max_contexts = 1` limits admission; it does not fix residual native
authentication state or multi-client object privacy. Those issues are planned
for [v0.3](v0.3.0-scope.md).

## What changed

The [`0.2.1` changelog](../../CHANGELOG.md) is authoritative. In brief:

- **Caller-NULL shape preservation (FIX-1).** `C_GetAttributeValue` query
  templates now carry an exact presence bit (`template_null`, proto field 6)
  from the shim through the daemon to the backend FFI, which materializes a
  real NULL for absent templates instead of an empty array. The daemon
  fail-closed rejects `template_null` with a non-empty payload. Proven
  against a REAL backend (Kryoptic): NULL-vs-empty is provider-observable,
  and the proxy now forwards each shape exactly.
- **Typed presence campaign (S2 R-wave).** Machine-checkable
  mechanism-parameter manifest with shape descriptors, resolver, and
  fingerprints; `Flat`/`Null` v1 wire schema (version 83); shim typed
  readers with presence emission; server transport validation
  (`PointerBytes`, `ValidatedMechanismParams`) at every site; backend
  Flat/Null FFI reconstruction with guarded backing; verbatim and
  completeness quality gates. Exotic-tail envelopes for the S2 section 8
  tail under decision D1(a).
- **Message-path fixes (S1/SDD).** Request-shape validation before session
  resolution, residual auth-blocking gates hoisted above the session lock,
  NULL/nonzero preservation on `VerifyMessageNext`, CK_ULONG-aligned
  provider-written query output, and the RF-MC-ORDER decision (a) pin:
  session arms stay SHI-first.
- **Interface truthfulness (RF-3.0).** Slot-provenance 3.0 advertisement
  with 3.0 to 3.1 to 3.2 dispatch, plus discovery of explicit `{3,1}`
  interfaces.
- **Win32 as a fourth v1 ABI.** Packed-32 model, `ParamAbi::native()` for
  32-bit Windows (ILP32), and CRLF-checkout manifest fixes.
- **Shim regression nets.** Read-after-destroy canary, NULL-shape
  termination/parity net (#30, #31), blocking slot-wait refusal with
  finalize regression (#25), async fixed-refusal 16-leg matrix (#24), and
  post-restart stale-handle `0x82` regression (#32).
- **Assurance.** Expanded Miri scope, cargo-fuzz harnesses with corrected
  seeds, Kani width-translation proofs adopted for the width laws,
  coverage ratchet, and secret-boundary canaries with attribute
  classifier laws.
- **Performance and packaging.** T1 perf comparator with receipts, RSA/EC
  keygen template parity gate, sign-pair latency bench receipts, degraded-
  operation control qualification (T3), direct-leg bench mode (T4), macOS
  arm64 bundle packaging with CI lanes and install doc.
- **Release engineering.** Single-invocation workspace repackaging, tag
  checkout with out-of-repo artifact staging, CI candidate resolution from
  the green tag run, cut-release dispatch fixes, and version-mirror checks.

The companion planning wrapper (kept private) adds the test-pool side of
this release: the F1-HMAC exact-empty bless seam, the `crash_mismatch`
robustness branch with 24 pinned shape-B rows, and a dated evidence pack.
Those change comparison tooling only, never proxy behavior.

## Current limits

All [v0.2.0 limits](v0.2.0-release-notes.md) carry forward, including the
single-client scope above, `CKF_DONT_BLOCK`-only slot events, no wiping or
complete audit tail on abnormal stop, startup-only attestation without
config hash, droppable data-plane audit records with gap reporting, and
fail-closed audit possibly occurring after a backend side effect.

New or restated for v0.2.1:

- The v1 typed-presence wire is decode-side only at the Phase 2 gate where
  noted; mixed shim/daemon versions remain unsupported.
- Session-arm differences stay SHI-first per RF-MC-ORDER decision (a);
  `AB-beats-stale-session` applies only with `sanitize_inputs` on, per the
  recorded spec-precedence pin (#23).
- A credential pointer that is NULL with nonzero length is refused locally
  with `CKR_ARGUMENTS_BAD` before RPC dispatch. This is a wire-format
  limit, not a general PKCS#11 rule about protected authentication.
- Backend token objects outlive the client's Finalize/Initialize cycle
  (known issue #27): logical Finalize removes only the client context,
  so memory-store objects survive where direct Finalize drops them.
  Per-client teardown is deferred to v0.3 multi-tenancy work.
