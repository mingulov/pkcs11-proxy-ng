# v0.2.2 Release Notes

**Status: `v0.2.2` release candidate; unpublished.** The source and packaging
versions are already `0.2.2`; publication remains gated by the quality receipt,
provider evidence, and tag procedure in the
[`0.x` release checklist](0.x-beta-release-checklist.md). This candidate
follows the published `v0.2.1` release; limits recorded in the
[v0.2.1 notes](v0.2.1-release-notes.md) still hold except where this file says
otherwise.

Use one logical client in one trusted security domain per daemon and provider
instance. Restart the daemon and provider before switching independent clients
or domains. Do not share an instance among mutually untrusted clients.
`[proxy] max_contexts = 1` limits admission; it does not fix residual native
authentication state or multi-client object privacy. Those issues are planned
for [v0.3](v0.3.0-scope.md).

## What changed

The [`0.2.2` changelog](../../CHANGELOG.md) is authoritative. In brief, three
v0.2.1 regressions reported as blockers by a real client project, each fixed
with failing-first regression tests and A/B base-vs-patched validation:

- **Daemon crash on message ChaCha20 init (#37).** `C_MessageEncryptInit`
  with `CK_CHACHA20_PARAMS` embedded client addresses in the forwarded
  opaque parameter image; the provider dereferenced them in the daemon
  process and crashed (SIGSEGV). A strict shape gate now admits only
  byte-buffer and parameterless shapes for unmodeled message-opaque
  bytes and fails closed on unknown shapes. The shim refuses locally
  with `CKR_MECHANISM_PARAM_INVALID` (zero RPC); server backstops cover
  message init, plain encrypt/decrypt init, and authenticated-wrap
  validation. Flat-byte opaque (e.g. CBC IV) and typed classic ChaCha20
  paths are byte-identical to before. A last-mile backstop re-checks
  admission at backend init construction against the request registry
  snapshot (review F-01); a `C_DestroyObject` now evicts the backend
  handle in every context, closing the daemon-mediated
  handle-recycling ABA leg (review F-02 — out-of-band provider
  mutation stays an accepted residual).
- **Private objects lost across logout/login (#35).** Providers that
  rotate private handles at logout stranded session-scoped objects: the
  proxy hid the rotated handles as foreign. Positively session-scoped
  (`CKA_TOKEN=false`) unmapped handles are now admitted when the
  session is the sole holder on the slot, with post-scan
  re-verification; shared-slot handles stay hidden per CROSS-PROC-001.
- **Certificates never found (#36).** Providers that omit `CKA_PRIVATE`
  when unset (absent means public) had their certificates hidden by the
  fail-closed carve-out. The mint-record fallback now admits
  recorded-public objects while recorded-private, unrecorded, and
  foreign handles stay hidden.

## Validation evidence

Dated evidence retained for this candidate (2026-10-05 unless noted):

- Rust workspace suite: 74/74 green (`cargo test --workspace` — 3798
  passed, 0 failed, 120 ignored), plus `fmt`, `clippy -D warnings`,
  and offline `check`.
- Revert controls: each fix's regression tests fail on the base tree
  (stash A/B for #37, mutation checks for #35/#36) and pass patched.
- Independent review: two read-only `codex` model reviews of the #37
  repair drove the strict-gate hardening (ScalarStruct refusal,
  fail-closed unknown, empty-init fail-fast, alternate-forms check,
  authenticated-wrap gate, doc/contract updates).
- Haskoki-faithful MockBackend semantics (unset attributes absent)
  underpin the #35/#36 regression tests; SoftHSM triage probes
  confirmed handle rotation is real provider behavior, not a filter
  artifact.

Known evidence gaps: no end-to-end run against the Haskoki binary was
available locally for #35/#36 (proven via faithful mocks plus SoftHSM
triage, not the reporting provider); the full non-mock provider matrix
comparison is deferred. Tagging and publication remain gated by the
open checklist boxes, including the explicit 30-provider non-mock
matrix required by [parity-validation.md](parity-validation.md).

## Current limits

All [v0.2.1 limits](v0.2.1-release-notes.md) carry forward, including the
single-client scope above.

New or restated for v0.2.2:

- Message-path mechanisms whose parameter shape is unmodeled are refused
  with `CKR_MECHANISM_PARAM_INVALID` instead of forwarding caller
  bytes; typed support for additional message parameter shapes is
  future work.
