# v0.3.0 Release Notes

**Status: `v0.3.0` release candidate; unpublished.** The source and packaging
versions are already `0.3.0`; publication remains gated by the quality receipt,
provider evidence, and tag procedure in the
[`0.x` release checklist](0.x-beta-release-checklist.md). This candidate
follows the published `v0.2.2` release; limits recorded in the
[v0.2.2 notes](v0.2.2-release-notes.md) still hold except where this file says
otherwise.

Use one logical client in one trusted security domain per daemon and provider
instance. Restart the daemon and provider before switching independent clients
or domains. Do not share an instance among mutually untrusted clients.
`[proxy] max_contexts = 1` limits admission; it does not fix residual native
authentication state or multi-client object privacy. Those issues are planned
for [a later version](v0.4.0-scope.md).

## What changed

v0.3.0 is a stabilization release with no new features: it ships the
engineering-audit remediation campaign on top of v0.2.2. In brief:

- Backend lifecycle hardening from the audit remediation (native
  ownership retention, finalize accounting, initialization-exposure
  recording), each with failing-first regression coverage.
- Operator documentation for every configuration knob with CI-enforced
  drift tests, a health contract for the readiness gate (latency
  metrics explicitly deferred), and repaired support tables plus
  canary/recovery runbooks.
- Assurance coverage: ceremony and operation-state end-to-end tests,
  wire-narrowing property tests, and recorded fuzz/Kani/Miri scope
  limits; Miri backend and shim-suites run clean under per-test gating
  for provider-loading tests.
- CI and release hardening: windows-2025 and win-arm64 legs promoted
  to voting, the cut-release MSRV gate aligned with the enforced
  locked all-targets build plus test suite, and shim connect errors
  that now name the endpoint, attempt count, and last failure.
- Dependency and lockfile maintenance, including rustls, rustls-webpki,
  and tokio security refreshes (see the dated `0.3.0` CHANGELOG section
  at release).

## Validation evidence

Evidence retained for this candidate (2026-10-26 unless noted):

- PR CI: full required gate set green (32 checks), including MSRV
  1.88, i686 narrow-`CK_ULONG`, LLP64, musl, and the cross-platform
  direct-vs-proxied legs.
- Miri backend pure-logic and shim parse-path suites green under the
  nightly gates; full workspace suite green with `fmt`, `clippy -D
  warnings`, and offline `check`.
- Independent review: subagent-driven implementation with per-task
  reviewers, fix loops, and a final whole-branch review, plus
  resumed `codex` model review rounds ending at APPROVE with zero
  findings above Minor.
- Revert controls: behavior fixes carry failing-first tests (new
  tests observed red before the fix, green after).

Known evidence gaps: the full non-mock provider matrix comparison is
deferred — it lands in v0.3.1, including the explicit 30-provider
non-mock matrix required by
[parity-validation.md](parity-validation.md). No end-to-end run
against every claimed provider backs this candidate; the published
qualification binding will point at the receipt, not at provider
results.

## Current limits
