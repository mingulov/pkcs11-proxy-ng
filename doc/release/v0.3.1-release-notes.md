# v0.3.1 Release Notes

**Status: `v0.3.1` released.**
The source and packaging versions are `0.3.1`. This release
follows the `v0.3.0` tag; limits recorded in the
[v0.3.0 notes](v0.3.0-release-notes.md) still hold except where this file says
otherwise. The provider-matrix qualification those notes placed in
v0.3.1 did not land; see Known gaps below.

Use one logical client in one trusted security domain per daemon and provider
instance. Restart the daemon and provider before switching independent clients
or domains. Do not share an instance among mutually untrusted clients.
`[proxy] max_contexts = 1` limits admission; it does not fix residual native
authentication state or multi-client object privacy. Those issues are planned
for [a later version](v0.4.0-scope.md).

## What changed

v0.3.1 is a release-process release with no proxy behavior changes: no
shim, daemon, client, or protocol code changed relative to v0.3.0. It
simplifies the release path for development speed (PR #56, on main as
`012960a..6bbb184`):

- `cut-release.yml`, `publish.yml`, and `release.yml` no longer
  require environment approvals (`release-tag`, `crates-io`,
  `release`) or the six provider-qualification inputs. The
  dispatcher is the sole authorizer.
- The `environments-preflight`, `qualification-preflight`, and
  `evidence-bind`/`evidence-verify` gates are deleted from the
  workflows and `scripts/release/` (two modules removed). The eight
  receipt gates, tag/CI binding, registry verification, and the
  non-destructive asset compare are unchanged.
- Release attestations now bind the tag commit and the candidate run
  instead of the removed qualification identity.
- A fail-closed `manifest-compatible` check keeps retries of
  pre-0.3.1 releases working: their retired qualification assets
  stay on the release untouched instead of wedging the manifest
  compare.
- The publishing guide, beta checklist, recovery runbook, and script
  inventory describe the new contract. The two retired contracts
  stay in `doc/release/` with RETIRED banners and can be restored
  from history if a gated flow is ever needed again.

## Validation evidence

Inherited evidence: the [v0.3.0 notes](v0.3.0-release-notes.md) record
the full baseline evidence, and this release adds no proxy code on
top of the v0.3.0 tag — only workflow, script, test, version-mirror,
and documentation changes.

This release's own evidence (PR #56):

- PR CI green 32/32 on the branch head, including the fail-closed
  aggregate and every platform lane; CI and Cross-platform success
  re-verified on main at the frozen subject `6bbb184`.
- Independent model review (`codex` rounds R1–R3) ending at APPROVE:
  two real findings (legacy-manifest retry regression, over-lenient
  comparator) fixed with failing-first tests, one stale-wording
  sweep, one deliberate non-change (matrix policy) agreed.
- Script suites green in PR CI, including the new
  manifest-compatibility unit tests and the workflow-ref wiring
  test; `sync-versions.sh --check` and the receipt battery green
  on this tree.

Known evidence gaps: the full non-mock provider matrix comparison
the v0.3.0 notes placed in this version did not land — no new date
is committed. Automated per-provider direct/proxied lanes are being
built out, but no green baselines exist yet, so no matrix claim
attaches to this release. This is the narrower-claim decision the
v0.3.0 notes left open, now recorded: v0.3.1 ships without
provider-matrix evidence and its support claims are unchanged from
v0.3.0.

## Current limits

All [v0.3.0 limits](v0.3.0-release-notes.md) carry forward, including the
single-client scope above.

New or restated for v0.3.1:

- Multi-client support is explicitly out of scope; see the [v0.4.0
  scope](v0.4.0-scope.md) for the deferred plan.
- Provider-matrix qualification is explicitly deferred again (see
  above); support claims are unchanged from v0.3.0.
