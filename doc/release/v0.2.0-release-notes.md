# v0.2.0 Testing Candidate Notes

**Status: unreleased testing candidate.** This source is being prepared as a
baseline for further testing. It does not establish public v0.2.0 provider
parity, production readiness, or completion of release qualification.

v0.2.0 is a **single-logical-client testing baseline**: use one trusted
security domain per daemon and provider instance. Do not connect mutually
untrusted clients or share a daemon/provider between independent domains.
Restart the daemon and its provider instance before changing to an independent
client or security domain. `[proxy] max_contexts = 1` is an admission guardrail,
not a repair for isolation or residual native authentication state.
Multi-client isolation is deferred to the [v0.3 scope](v0.3.0-scope.md).

## Implemented changes

The `[Unreleased]` changelog records gateway authorization and quotas,
resilience controls, audit and startup attestation, native ownership/lifecycle
and stop enforcement, width bridging, platform infrastructure, and
provider-transparency corrections. The latest corrections forward admitted
login attempts to the backend, preserve metadata-object visibility, track
explicitly destroyed handles, and extend mechanism parameter conversion and
registry defaults. Present zero-capacity attribute buffers preserve their
original capacity and native output semantics, including unchanged caller
storage. Successful copies use the copied object's actual `CKA_TOKEN` value
when available to choose virtual-handle lifetime; the metadata fallback is
explicitly limited below. Focused direct/proxy SoftHSM2 checks exercised these
attribute and copy cases. They do not establish cross-ABI or NSS qualification.
Classic CCM now preserves IV/AAD NULL flags through the mechanism conversion
paths. A real Kryoptic client-to-FFI encrypt/decrypt check covered a valid
12-byte nonce with empty AAD both NULL and present, recovering the plaintext
with a 16-byte MAC. Kryoptic accepts both AAD forms: this live check proves
operation success, while separate shim/protobuf/FFI structural tests check
pointer presence. Other CCM pointer shapes, CCM/wrap layouts and other
providers remain unqualified by that check; local NSS and SoftHSM2 did not
advertise CCM. Mixed shim/daemon versions remain unsupported.

Cargo workspace metadata is authoritative for the version and MSRV; packaging
and CI literals are checked mirrors.

## Platform coverage and limits

The [native ownership contract](native-mechanism-ownership.md) and
[ADR-0014](../adr/ADR-0014-v020-tail-platform-stretch.md) record implemented
platform boundaries and historical tests. Those records are tied to their
original revisions and environments; final-candidate qualification is separate.

- Linux x86_64/i686: four loaded-shim caller/daemon width combinations, with
  SoftHSM2 and an additional NSS-i386 leg. The x86_64 musl tier distinguishes
  static CLI from the dynamic daemon/shim required for provider loading; see
  [musl-tier.md](musl-tier.md).
- Windows x64/MSVC: historical real-Windows daemon and shim interoperation in
  both directions, plus compile and packaging infrastructure. The Windows
  daemon uses mTLS over TCP and rejects `[listener.local]`.
- Linux aarch64: a blocking runtime comparison CI leg; the stop arm has
  compile/review evidence but no native stop-fire receipt.
- Windows x86/MSVC: build, WOW64 suites and a stub-provider live-load tier;
  production 32-bit provider behavior remains unqualified.
- macOS aarch64: historical runtime comparison and library/stop tests.
  macOS x86_64 has load coverage only.
- s390x: build and [QEMU suites](be-qemu-tier.md), with live native FFI excluded.
  Windows GNU is excluded; Wine smoke is development evidence only.

Build/CI configuration and historical receipts do not by themselves qualify
this testing candidate on those platforms or providers. Historical private
workspace artifacts are not a portable public qualification bundle.

## Current limitations

- The implemented [native ownership contract](native-mechanism-ownership.md)
  requires one managed provider chain per process, reservation before native
  loading, and explicit retirement. Direct embedders share one Arc and accept
  whole-process failure; independent chains require separate processes.
  Multiple backend runtime copies, unmanaged native access and downstream
  aggregator aliasing remain excluded.
- Slot-event scope is `CKF_DONT_BLOCK` only. Blocking mode returns local
  `CKR_FUNCTION_NOT_SUPPORTED` without polling. Clients compete for shared
  native pending flags; logical Initialize creates no independent event bitmap.
  Checked widths, error precedence and one ordinary-lifecycle waiter remain
  part of the contract.
- Native construction and abnormal stops retain the exact target/environment
  boundaries in the ownership contract. Code admission, a compile check or a
  stub-provider test is not a general live-provider support claim.
- The selected abnormal stop promises no wiping, complete audit tail, provider
  cleanup, token deletion, strict disappearance deadline or global core-dump
  suppression; its exact target/seccomp/environment limits are documented in
  the native ownership contract and [privacy contract](privacy.md).

- Credential inputs with a NULL pointer and nonzero length are outside the
  supported wire representation. The shim refuses them locally with
  `CKR_ARGUMENTS_BAD` before RPC dispatch. This is a transport/input limit,
  not a claim that PKCS#11 universally forbids that shape: protected
  authentication paths can use a NULL PIN without requiring length zero.
  See [ADR-0010](../adr/ADR-0010-transparent-forwarding-by-default.md).
- After a successful native `C_CopyObject`, the proxy reads the copied object's
  actual `CKA_TOKEN` to determine handle lifetime, retaining a valid explicit
  template value when the provider value is unavailable. If lifetime still
  cannot be established, it preserves native success and records a session-scoped
  virtual handle. That handle can expire when the copying session closes even
  if the native object persists. This is an explicit metadata/handle-lifetime limit.
- Denial is not constant-latency.
- Diagnostic bundles are private, allowlisted metadata snapshots. They exclude
  raw logs, configuration files, environment values, and command errors, and
  use descriptor-relative, create-only Python standard-library archive output
  rather than external archive tools. They must still be reviewed before
  sharing. Arbitrary-log sanitization is not a supported promise.
- Attestation runs at startup only; it has no config hash and no reconnect or
  hot-swap re-attestation.
- Audit contains operational metadata, never PINs, key material, or raw request
  payloads.
- Data-plane audit can drop records and reports gaps.
- Fail-closed audit can occur after a backend side effect.
- `EventClass::Deny` remains reserved rather than emitted.

## Remaining gates

For the testing baseline, resolve correctness findings within the single-client
scope, validate the final source including accepted pending changes, reconcile
tests with the intended contracts, and record the commands and true outcomes. Failed or
incomplete evidence remains visible; it must not be relabeled as a pass.

Before a qualified release:

- Obtain current-candidate ownership, lifecycle, width, stop and platform
  evidence for each claimed target and environment.
- Record the framework, test-data, provider, configuration and selection
  identities, together with exact source and binary identities.
- Complete direct/proxy comparisons for the intended provider scope, including
  the explicit 30-provider non-mock matrix, and disposition every mismatch.
- Pass the standalone-clone gate and produce a new source-bound quality receipt.
- Follow the release workflow's frozen-subject/receipt commit topology.
- Obtain separate approval to tag, push and publish.

## Explicit exclusions

This candidate has no Observatory, recorder or payload capture, target replay,
cassette playback, live mirror, or public `v0.2.0` artifact.
