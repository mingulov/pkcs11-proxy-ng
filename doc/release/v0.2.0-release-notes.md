# v0.2.0 Release Notes

**Status: local candidate; unreleased.** Public latest is `v0.1.0`; the local
target is `v0.2.0`.

## Local changes

The `[Unreleased]` changelog records local gateway work: opt-in gateway
authorization and rate/quota controls; resilience detection and attribute
coalescing; tamper-evident audit with data-plane gap reporting; startup backend
attestation; transparent-forwarding fixes for NULL/data forwarding and bounds,
mechanism-payload safety, Verify/Digest init forwarding, and close-attempt
session-cache eviction;
packaging mirrors for Alpine APK, Amazon Linux RPM, and CI; and workspace MSRV
`1.88`. Cargo workspace metadata is authoritative; APK/RPM/CI literals are
checked mirrors. This work is implemented locally, partially covered, and
unreleased; local unit and integration coverage is not a transparency matrix.

## Current limitations

- The selected [native ownership contract](native-mechanism-ownership.md)
  remains unimplemented/unqualified: one managed provider chain per process,
  constructor reservation before loading/discovery, explicit native retirement,
  and a qualified raw Linux `exit_group(70)` last-owner/shutdown backstop.
  Direct embedders share one Arc and accept whole-process failure; independent
  chains require separate processes. Multiple backend runtime copies, unmanaged
  native access and downstream aggregator aliasing are excluded.
- v0.2 slot-event scope is `CKF_DONT_BLOCK` only. Blocking mode is locally
  FUNCTION_NOT_SUPPORTED without polling. Clients share native pending-event
  flags; logical Initialize creates no independent event bitmap. Checked widths,
  error precedence and the one ordinary-lifecycle waiter remain release gates.
- Live FFI qualification is Linux GNU/musl x86_64/64-bit and x86/32-bit only.
  Windows native-provider daemon support was withdrawn/deferred for v0.2 and is
  re-admitted as committed tail stretch (low priority, before the comprehensive
  matrix gate) per [ADR-0014](../adr/ADR-0014-v020-tail-platform-stretch.md): Windows x64
  daemon plus Windows x64 client shim, both interoperation directions, and the
  32-bit/mixed claim. Until then, portable Windows client/shim/proto/types,
  mock-only server/backend and Windows-client/Linux-daemon interoperation remain,
  and nonqualified hosts must refuse FFI construction before native loading.
- The selected abnormal stop promises no wiping, complete audit tail, provider
  cleanup, token deletion, strict disappearance deadline or global core-dump
  suppression; its exact target/seccomp/environment limits are documented in
  the native ownership contract and [privacy contract](privacy.md).

- Denial is not constant-latency.
- Diagnostic bundles are private, allowlisted metadata snapshots. They exclude
  raw logs, configuration files, environment values, and command errors, and
  use descriptor-relative, create-only Python standard-library archive output
  rather than external archive tools. They must still be reviewed before
  sharing. Arbitrary-log sanitization is not a supported promise.
- Attestation runs at startup only; it has no config hash and no reconnect or
  hot-swap re-attestation.
- Audit contains operational metadata, never PINs, key material, or raw request
  payloads.
- Data-plane audit can drop records and reports gaps.
- Fail-closed audit can occur after a backend side effect.
- `EventClass::Deny` remains reserved rather than emitted.
