# v0.2.0 Release Notes

**Status: `v0.2.0` release candidate; unpublished.** The source and packaging
versions are already `0.2.0`; publication remains gated by the quality receipt,
provider evidence, and tag procedure in the
[`0.x` release checklist](0.x-beta-release-checklist.md).

## Local changes

The `[Unreleased]` changelog records local gateway work: opt-in gateway
authorization and rate/quota controls; resilience detection and attribute
coalescing; tamper-evident audit with data-plane gap reporting; startup backend
attestation; transparent-forwarding fixes for NULL/data forwarding and bounds,
mechanism-payload safety, Verify/Digest init forwarding, and close-attempt
session-cache eviction;
packaging mirrors for Alpine APK, Amazon Linux RPM, and CI; and workspace MSRV
`1.88`. Cargo workspace metadata is authoritative; APK/RPM/CI literals are
checked mirrors. This work is implemented locally, partially covered, and
unreleased; local unit and integration coverage is not a transparency matrix.

## Current limitations

- The selected [native ownership contract](native-mechanism-ownership.md)
  remains unimplemented/unqualified: one managed provider chain per process,
  constructor reservation before loading/discovery, explicit native retirement,
  and a qualified raw Linux `exit_group(70)` last-owner/shutdown backstop.
  Direct embedders share one Arc and accept whole-process failure; independent
  chains require separate processes. Multiple backend runtime copies, unmanaged
  native access and downstream aggregator aliasing are excluded.
- v0.2 slot-event scope is `CKF_DONT_BLOCK` only. Blocking mode is locally
  FUNCTION_NOT_SUPPORTED without polling. Clients share native pending-event
  flags; logical Initialize creates no independent event bitmap. Checked widths,
  error precedence and the one ordinary-lifecycle waiter remain release gates.
- Live FFI is qualified on Linux GNU/musl x86_64/64-bit and x86/32-bit, and on
  Windows x64/MSVC per the evidenced scope above; nonqualified hosts must still
  refuse FFI construction before native loading. Still excluded: Windows GNU.
  Linux ARM64 is runtime-qualified (cross-platform ubuntu-26.04-arm leg
  enabled, blocking). 32-bit Windows (PE32) is qualified at the win32 CI tier
  (build, WOW64 suites, stub live-load — stub boundary); macOS aarch64
  is runtime-qualified (T2run first green macOS leg), macOS x86_64
  load-qualified only. Big-endian is proven
  one tier below a runtime claim (s390x build + QEMU suites green, no live
  BE FFI); see [be-qemu-tier.md](be-qemu-tier.md).
- The selected abnormal stop promises no wiping, complete audit tail, provider
  cleanup, token deletion, strict disappearance deadline or global core-dump
  suppression; its exact target/seccomp/environment limits are documented in
  the native ownership contract and [privacy contract](privacy.md).

- Denial is not constant-latency.
- Diagnostic bundles are private, allowlisted metadata snapshots. They exclude
  raw logs, configuration files, environment values, and command errors, and
  use descriptor-relative, create-only Python standard-library archive output
  rather than external archive tools. They must still be reviewed before
  sharing. Arbitrary-log sanitization is not a supported promise.
- Attestation runs at startup only; it has no config hash and no reconnect or
  hot-swap re-attestation.
- Audit contains operational metadata, never PINs, key material, or raw request
  payloads.
- Data-plane audit can drop records and reports gaps.
- Fail-closed audit can occur after a backend side effect.
- `EventClass::Deny` remains reserved rather than emitted.

# v0.2.0 Testing Candidate Notes

**Status: unpublished release candidate.** Publication remains gated by the
source-bound quality receipt, provider evidence, and tag procedure in the
[`0.x` release checklist](0.x-beta-release-checklist.md). The
[support matrix](beta-support-matrix.md) describes published support.

Use one logical client in one trusted security domain per daemon and provider
instance. Restart the daemon and provider before switching independent clients
or domains. Do not share an instance among mutually untrusted clients.
`[proxy] max_contexts = 1` limits admission; it does not fix residual native
authentication state or multi-client object privacy. Those issues are planned
for [v0.3](v0.3.0-scope.md).

## What changed

The [unreleased changelog](../../CHANGELOG.md) covers gateway authorization
and quotas, resilience, audit and startup attestation, native ownership,
cross-width support, platform work, and provider-transparency fixes. Recent
changes preserve admitted backend login attempts, metadata-object visibility,
and native output behavior for present zero-capacity attribute buffers.
Copied-object handle lifetime now uses the copied object's `CKA_TOKEN` value
when available.

Classic CCM conversion preserves whether IV and AAD pointers are NULL. A
Kryoptic live encrypt/decrypt check succeeded with both NULL and present empty
AAD for one valid nonce and MAC size. Structural tests cover pointer presence.
That check does not qualify other CCM shapes or providers; local NSS and
SoftHSM2 did not advertise CCM. Mixed shim/daemon versions are unsupported.

Cargo workspace metadata is the source for the version and minimum Rust
version; packaging and CI values are checked copies.

## Current limits

- One managed provider chain is required per process. Independent chains need
  separate processes. Unmanaged native access, additional runtime copies, and
  downstream aggregator aliases are excluded. The
  [native ownership contract](native-mechanism-ownership.md) gives the exact
  reservation, retirement, target, and abnormal-stop rules.
- `C_WaitForSlotEvent` accepts `CKF_DONT_BLOCK` only. Blocking calls return
  local `CKR_FUNCTION_NOT_SUPPORTED`. Clients share native per-slot pending
  flags; a logical Initialize does not create an independent event bitmap.
- The selected abnormal whole-process stop does not promise wiping, a complete
  audit tail, provider cleanup, token deletion, a strict disappearance
  deadline, or global core-dump suppression. See the
  [ownership](native-mechanism-ownership.md) and [privacy](privacy.md) contracts.
- A credential pointer that is NULL with nonzero length is refused locally
  with `CKR_ARGUMENTS_BAD` before RPC dispatch. This is a wire-format limit,
  not a general PKCS#11 rule about protected authentication.
- After a successful native `C_CopyObject`, if object lifetime cannot be
  established from `CKA_TOKEN` or a valid template value, the proxy keeps
  native success and assigns a session-scoped virtual handle. The handle may
  expire on session close while the native object remains.
- Denial timing is not constant. Startup attestation has no config hash or
  reconnect/hot-swap re-attestation.
- Diagnostic bundles contain allowlisted metadata and exclude raw logs,
  configuration files, environment values, and command errors. Review them
  before sharing; arbitrary-log sanitization is not promised.
- Audit records operational metadata, not PINs, keys, or raw request payloads.
  Data-plane records may be dropped with reported gaps; fail-closed audit may
  occur after a backend side effect. `EventClass::Deny` is reserved.
