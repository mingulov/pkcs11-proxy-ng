# `0.x` Beta Release Checklist

Gate for tagging a public `0.x` beta. Every item must be true and evidenced — do
not check an item for intended-but-unverified work.

The current source and packaging version is `v0.2.0`. Until the annotated
`v0.2.0` tag and release artifacts are published, the tree is a release
candidate. Keep every box open until dated, provenance-complete evidence
satisfies it.

## Build & quality (standalone)

The repository must pass on its own, with no outer workspace and no OASIS tree:

- [ ] `cargo fmt --all -- --check` clean
- [ ] `cargo check --workspace --all-targets --locked` clean
- [ ] `cargo test --workspace --locked` green (OASIS-source-grounded tests skip cleanly
      when `PKCS11_PROXY_NG_OASIS_ROOT` is unset)
- [ ] `scripts/release-dry-run.sh` produces the expected artifacts
- [ ] Verified from a fresh clone of *this repository alone* (not via the
      planning workspace)
- [ ] Intended check commit and clean framework/test-data provenance recorded

## Parity evidence

The nightly workflow is a code/CI gate; it does not replace this source-bound
direct-versus-proxied release evidence.

See [parity-validation.md](./parity-validation.md). For each of SoftHSM2, NSS
softokn, Kryoptic:

- [ ] Full suite run direct and proxied
- [ ] Dated direct, proxied, and comparison artifacts retain complete provenance
- [ ] Explicit 30-provider non-mock matrix completed and retained with provenance
- [ ] Outcome classes compared; mismatches triaged (provider-specific / proxy
      bug / known issue). Provider-conformance fixes stay out of proxy
      scope: proxy bugs fixed here, provider issues reported upstream and
      recorded, never normalized by the proxy (see the
      [parity triage rules](parity-validation.md#triage-of-mismatches))
- [ ] No open release-blocking proxy bug
- [ ] Residual differences recorded in the [support matrix](./beta-support-matrix.md)

## Documentation

- [ ] README beta-scope matches the [support matrix](./beta-support-matrix.md)
- [ ] [mtls-setup.md](./mtls-setup.md) reflects the real config fields and the
      private-key permission requirement
- [ ] [Operator runbook](../runbooks/operating-pkcs11-proxy-ng.md) current
- [ ] [error-reference](../error-reference.md) current
- [ ] ADRs reflect public released behavior and mark local unreleased increments
      accurately (incl. ADR-0006 32-bit-deferred, ADR-0007 crash isolation)

## Support-claim discipline

- [ ] Support matrix claims only what the evidence supports
- [ ] Plain TCP without mTLS still documented as **not** a public claim (unless
      an explicit decision has changed that)
- [ ] No "production-ready" or broad-vendor language anywhere public
- [ ] LICENSE(s) present; crate metadata (`version`, `license`, and ideally
      `repository`/`description`) set for the release

## Freeze and publish

- [ ] Version in `Cargo.toml` `[workspace.package]` and all checked packaging
      mirrors is `0.2.0`
- [ ] Release notes summarize scope, validated matrix, and known limitations
- [ ] GitHub environment `release` exists before the tag is pushed, has a
      required reviewer, and restricts deployment to the intended release tags
- [ ] All release code and documentation are committed in one frozen subject
      commit; its full SHA is used for every qualification run
- [ ] `doc/release/v0.2.0-quality-receipt.md` names that frozen subject and
      records `pass` for `fmt`, `check`, `test`, `clippy`, `msrv`, `audit`,
      `deny`, and `release_dry_run`
- [ ] A final bookkeeping commit changes only `CHANGELOG.md` and the quality
      receipt; `CHANGELOG.md` contains `## [0.2.0] - YYYY-MM-DD`
- [ ] The bookkeeping commit passes:

      ```bash
      scripts/verify-release-subject.sh v0.2.0
      scripts/test-verify-quality-receipt.sh
      GITHUB_REF_NAME=v0.2.0 scripts/release-dry-run.sh
      ```

- [ ] From the clean bookkeeping commit, create and push the exact final tag:

      ```bash
      git tag -a v0.2.0 -m "pkcs11-proxy-ng v0.2.0"
      git push origin v0.2.0
      ```

- [ ] Required reviewer approves the `release` deployment only after both build
      jobs pass
- [ ] Published release contains the Linux archive, Windows ZIP,
      `SHA256SUMS`, and `SHA256SUMS-windows`; both checksum files verify
