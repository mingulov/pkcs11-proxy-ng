# `0.x` Beta Release Checklist

Use this checklist before tagging a public beta. Leave a box open until the
result is verified for the exact release source and its evidence is retained.
Candidate-specific scope and limitations belong in its release notes. Published
versions and artifacts are listed on
[GitHub Releases](https://github.com/mingulov/pkcs11-proxy-ng/releases).

The current source and packaging version is `v0.2.2`. Until the annotated
`v0.2.2` tag and release artifacts are published, the tree is a release
candidate. Keep every box open until dated, provenance-complete evidence
satisfies it.

## Build and quality

Verify the repository from a fresh clone, without the private planning
workspace or an OASIS source tree:

- [ ] `cargo fmt --all -- --check` is clean
- [ ] `cargo check --workspace --all-targets --locked` is clean
- [ ] `cargo test --workspace --locked` passes, including local shape and
      real-backend-driver completeness checks
- [ ] `scripts/release-dry-run.sh` produces the expected artifacts
- [ ] The exact source commit, test suite, test data, and results are recorded

## Provider comparisons

- [ ] `cargo fmt --all -- --check` clean
- [ ] `cargo check --workspace --all-targets --locked` clean
- [ ] `cargo test --workspace --locked` green, including local shape and
      real-backend-driver completeness checks
- [ ] `scripts/release-dry-run.sh` produces the expected artifacts
- [ ] Verified from a fresh clone of *this repository alone* (not via the
      planning workspace)
- [ ] Intended check commit and clean framework/test-data provenance recorded

## Parity evidence

The nightly workflow is a code/CI gate; it does not replace this source-bound
direct-versus-proxied release evidence.

See [parity-validation.md](./parity-validation.md). For each of SoftHSM2, NSS
softokn, Kryoptic:

- [ ] Full suite run direct and proxied
- [ ] Dated direct, proxied, and comparison artifacts retain complete provenance
- [ ] Explicit 30-provider non-mock matrix completed and retained with provenance
- [ ] Outcome classes compared; mismatches triaged (provider-specific / proxy
      bug / known issue). Provider-conformance fixes stay out of proxy
      scope: proxy bugs fixed here, provider issues reported upstream and
      recorded, never normalized by the proxy (see the
      [parity triage rules](parity-validation.md#triage-of-mismatches))
- [ ] No open release-blocking proxy bug
- [ ] Residual differences recorded in the [support matrix](./beta-support-matrix.md)

## Documentation

- [ ] README beta-scope matches the [support matrix](./beta-support-matrix.md)
- [ ] [mtls-setup.md](./mtls-setup.md) reflects the real config fields and the
      private-key permission requirement
- [ ] [Operator runbook](../runbooks/operating-pkcs11-proxy-ng.md) current
- [ ] [error-reference](../error-reference.md) current
- [ ] Documentation distinguishes released behavior from unreleased changes
- [ ] ADRs reflect public released behavior and mark local unreleased increments
      accurately (incl. ADR-0006 32-bit-deferred, ADR-0007 crash isolation)

## Support-claim discipline

- [ ] Support matrix claims only what the evidence supports
- [ ] Plain TCP without mTLS still documented as **not** a public claim (unless
      an explicit decision has changed that)
- [ ] No "production-ready" or broad-vendor language anywhere public
- [ ] LICENSE(s) present; crate metadata (`version`, `license`, and ideally
      `repository`/`description`) set for the release

## Freeze and publish

- [ ] Version in `Cargo.toml` `[workspace.package]` and checked packaging
      mirrors matches the intended tag
- [ ] Release notes state the scope, validated providers, and limitations
- [ ] GitHub environment `release` exists before the tag is pushed, requires a
      reviewer, and is restricted to intended release tags
- [ ] Code and documentation are frozen in one subject commit; all qualification
      uses its full SHA
- [ ] The matching versioned quality receipt names that subject and records
      exactly `pass` for `fmt`, `check`, `test`, `clippy`, `msrv`, `audit`,
      `deny`, and `release_dry_run`
- [ ] A final bookkeeping commit changes only `CHANGELOG.md` and the quality
      receipt; the changelog contains a dated heading for the intended version
- [ ] The bookkeeping commit passes:

      ```bash
      export TAG=vX.Y.Z
      scripts/verify-release-subject.sh "$TAG"
      scripts/test-verify-quality-receipt.sh
      GITHUB_REF_NAME="$TAG" scripts/release-dry-run.sh
      ```

- [ ] Separate approval has been received to create and push the exact tag:

      ```bash
      git tag -a "$TAG" -m "pkcs11-proxy-ng $TAG"
      git push origin "$TAG"
      ```

- [ ] The required reviewer approves the `release` deployment only after the
      registry-source binary builds and native smokes pass
- [ ] The published release contains the Linux archive, Windows ZIP,
      `inventory.json`, and `qualification-binding.json`; the
      compare-then-stage gate verified the staged set

## crates.io publication and registry-source binaries

See the [publication guide](./crates-io-publishing.md) for the machinery;
record the run here.

- [ ] Protected environments exist before dispatch: `crates-io` (required
      reviewers, tag restrictions, bound to the qualification record),
      `crates-io-staging` (separate account/endpoint/token), `release`
      (required reviewers, tag restrictions), plus `release-tag`
      (required reviewers) when cutting via the orchestrator
- [ ] Either the orchestrator path (`cut-release.yml` dispatched from the
      GUI with version/mode/package/qualification; verify green, tag
      approval granted, publish auto-dispatched) or the manual path
      below was followed; partial states recovered by hand as guided
- [ ] Qualification record complete: exact HTTPS URL plus the frozen
      subject SHA; approval inputs published to the preflight summary
- [ ] Staging probe published from `main` first; ordinary dry-runs stayed
      upload-free
- [ ] `publish.yml` dispatched from the exact tag with the intended mode
      (`dry-run`, `bootstrap`, or `trusted`) and package selection;
      bootstrap used only until one trust record per crate exists
- [ ] Required reviewer approved the `crates-io` deployment against the
      preflight summary
- [ ] Full CI, artifact smokes, all-eight checksum verification, and
      registry consumers green; `complete=true` emitted before any
      binary build started
- [ ] Partial publication, if any, recovered by individual-member
      dispatch; the follow-up command from the run was used
- [ ] Required reviewer approved the `release` deployment only after the
      registry-source binary builds and native smokes passed
- [ ] Release assets compared before publication: identical retained,
      missing added, none divergent; no tag moved, replaced, or deleted
- [ ] Pre-auth candidate, post-upload evidence, and release assets
      retained (90-day run artifacts) and escrowed to maintainer
      long-term storage with the location recorded in the release notes
- [ ] docs.rs builds confirmed for all eight crates after publication
