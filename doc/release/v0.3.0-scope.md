# Planned v0.3 Multi-client Support

This is planned work, with no delivery-date or support commitment. The
unreleased v0.2 testing candidate is limited to one logical client and one
trusted security domain per daemon/provider instance. Restart both before
switching independent clients or domains. `max_contexts = 1` limits
admission; it does not clear native authentication state or isolate private
objects.

Before claiming multi-client support, the project needs to:

- Track object privacy, including provider defaults and unknown states, and
  invalidate cached decisions when objects or sessions change.
- Coordinate login and private operations through completion of the native
  call, including timeouts, cancellation, and authentication state left behind
  by interrupted work.
- Test client handover, identity, object visibility, login/logout, operation
  authorization, teardown, failures, and concurrent native calls with
  adversarial multi-client cases. Keep provider findings and exact `CK_RV`
  values visible.
- Qualify the final candidate on each claimed provider, platform, transport,
  and native-lifetime path. Build, stub load, runtime, and provider comparison
  results each have their own scope.

Independent security domains still need separate daemon/provider instances.
Sharing an external token or HSM across those instances needs its own
qualification. [Public support](beta-support-matrix.md) expands only after
implementation, evidence, and independent review establish the new contract.
